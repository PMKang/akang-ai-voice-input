# 弱网环境转写降级设计

状态：已确认，待实现。

## 目标

弱网环境可以牺牲实时出字速度，但不能因为实时 WebSocket 延迟、乱序、超时或断线要求用户重新说一遍。

成功标准：

- 正常网络继续边说边出字，不增加可感知等待。
- 录音期间始终在本地保留一份完整音频，实时链路异常不丢内容。
- 检测到服务端响应明显变慢时，不指责用户网络，只说明转写需要更多时间。
- 实时结果不可信或缺失时，停止录音后自动使用完整录音做文件识别。
- 完全断网时保留待处理任务，网络恢复后自动继续；只有任务最终失败时才要求用户操作。

## 方案比较

### 方案 A：只保留实时识别并增加提示

改动最小，但只能解释等待，无法解决会话超时、结果不完整和断线丢失。不能满足“不用重说”的核心目标。

### 方案 B：录音中途切换另一条实时模型

可能恢复实时预览，但另一条云链路同样受弱网影响，而且模型间的断句、标点和增量语义不同。中途拼接容易重复或漏字，不作为首选。

### 方案 C：实时快通道 + 本地完整录音 + 文件识别兜底

正常时使用当前流式 ASR；同时在本地落盘完整音频。实时链路异常时不在录音中途换模型，用户停止后用完整录音重新识别。该方案兼顾正常速度和弱网完整性，作为推荐方案。

端侧识别可在后续作为弱网草稿预览增强，但不属于首期可靠性闭环。

## 用户体验

### 正常录音

悬浮条继续显示声波和实时文字。用户无需知道本地还保存着临时音频。

### 响应变慢

满足以下条件时进入 `degradedListening`：

- 已采集到达到有效人声阈值的 PCM；
- 开始录音后 5 秒仍未收到第一段非空转写，或收到过文字后连续 8 秒无新的服务端识别结果；
- 或实时客户端报告发送积压、协议错误、连接异常。

展示文案：

> 当前网络响应较慢，转写可能比平时需要更长时间，请耐心等待。

声波和计时继续运行，用户可以继续说。第一段新文字返回后可以恢复实时文字，但本次会话仍标记为“曾降级”，停止后需要检查是否使用文件兜底。

### 停止录音

- 实时会话健康且正常返回最终结果：直接写入。
- 实时会话曾降级、超时、断线、协议报错或最终文字为空：悬浮条进入“正在完成转写”，后台提交完整录音文件识别。
- 文件识别期间沿用提示：`当前网络响应较慢，转写可能比平时需要更长时间，请耐心等待。`
- 文件识别完成：写入完整结果并删除临时音频。
- 当前无网络：展示 `录音已保存，将在网络恢复后自动完成转写。`，任务进入待重试队列。

## 数据流

```text
麦克风 PCM
   ├─> 实时 ASR（快速通道）──> 实时预览 / 健康状态
   └─> 本地 WAV 临时文件（完整性通道）

停止录音
   ├─ 实时健康 + 最终结果完整 ──> 写入文字 ──> 删除 WAV
   └─ 实时异常或结果缺失 ──> 文件 ASR ──> 写入文字 ──> 删除 WAV
                                  │
                                  └─ 网络不可用 ──> 持久化任务并自动重试
```

## 组件设计

### `SessionAudioArchive`

负责把经过现有语音门控后的 16 kHz、单声道、16-bit PCM 顺序写入临时 WAV。它只管理音频文件生命周期，不判断网络和模型状态。

- 会话开始创建文件。
- 每个有效 PCM 块同时传给实时客户端并追加到文件。
- 停止时补齐 WAV 头并关闭文件。
- 成功输出后删除；待重试时保留。
- 文件名使用随机 UUID，不包含转写正文。

### `RealtimeHealthTracker`

只根据可观测事件判断当前会话是否健康：首字时间、最后服务端文字时间、连接错误、协议错误和是否取得最终结果。`NWPathMonitor` 仅作为“彻底离线”的辅助信号，不能单独代表网络质量。

状态：

- `healthy`
- `slow`
- `failed`

一旦会话进入 `failed`，不再把本次实时最终文本当作唯一可靠结果；进入 `slow` 后即使恢复，也记录 `requiresIntegrityCheck = true`。

### `RecordingFileTranscriptionClient`

首期复用豆包账户凭证，调用豆包大模型录音文件极速识别。输入为本地 WAV 二进制，输出为完整文本。它与实时 WebSocket 客户端分离，避免混用协议状态。

调用需要具备：

- 明确的请求超时；
- 可区分的网络错误、鉴权错误、限流和服务端错误；
- 相同任务幂等，避免网络恢复后重复写入文字。

### `PendingTranscriptionStore`

保存待处理任务的最小元数据：任务 UUID、WAV 路径、创建时间、目标输入框上下文是否仍可用、重试次数和下次重试时间。不得保存 API Key 或转写正文。

重试采用有上限的指数退避。应用启动或网络从不可用恢复为可用时触发。若原输入焦点已失效，完成结果进入剪贴板和历史记录，并明确通知用户。

## 结果选择

不把实时文本和文件文本做字符级拼接：

- 实时健康时使用实时最终结果。
- 触发文件兜底时，以完整文件识别结果整体替换实时预览。
- 文件识别失败但已有非空实时最终结果时，可在明确标记“可能不完整”的情况下提供恢复入口，不自动静默写入疑似残缺文本。

## 隐私与清理

- 临时录音仅保存在应用支持目录，不进入诊断报告、历史正文导出或遥测。
- 正常完成后立即删除。
- 待重试录音最多保留 24 小时；超过期限提示用户任务未完成并提供删除或手动重试。
- 应用提供“一键清除待转写录音”。
- 诊断只记录字节数、持续时间、状态和错误类别，不记录音频或转写正文。

## 测试范围

- PCM 同时按原顺序进入实时发送队列和 WAV 文件。
- WAV 头、采样率、声道与文件长度正确。
- 5 秒首字延迟触发文案；未检测到有效人声时不误报。
- 实时正常完成时不调用文件识别。
- 实时超时、断线、协议错误和空结果均调用文件识别。
- 文件识别成功只写入一次并删除临时文件。
- 断网任务跨应用重启保留，恢复网络后重试。
- 过期任务和手动清理能够删除音频。
- 诊断与持久化元数据不包含凭证和转写正文。

## 首期边界

首期不做：

- 录音中途切换实时模型；
- 实时结果与文件结果的字符级合并；
- 内置 Whisper 等额外本地模型；
- 用户手动选择“实时或文件模式”。

这些能力只有在双通道闭环经过弱网实测后再评估。
