# v1.8.0：我给 AI 语音输入法补的，不是一个悬浮窗，而是“别打扰人”的能力

这次 macOS v1.8.0，重点更新了三件事：

- 语音输入悬浮窗支持展开、收起和贴边三种状态，并能拖动；
- 拖过一次后，位置和展开/收起状态会被记住，录音、处理和下一次唤起保持同一个锚点；
- 补上长时间静音的会话保活，以及下一次闪退后可查看的本地诊断记录。

如果只看功能清单，这一版很容易被理解成一次界面优化。

但它真正解决的，是我高频使用里一个非常具体的问题：语音输入本来应该帮我输入，却开始挡住我正在用的软件。

![语音输入悬浮窗挡住 ChatGPT 的模型选择菜单](../images/v1.8.0-chatgpt-model-picker-obscured.png)

这是我在 ChatGPT 里切模型时截下来的画面。模型菜单刚好在底部弹出，自在说的语音输入条也固定在底部，于是两个东西正面撞上。

当时我不是在做什么复杂操作，只是想切一下模型。但悬浮条恰好把菜单盖住了。

一个输入工具，反过来阻断了输入前的正常操作。这件事很小，但我觉得不能接受。

## 问题不是“悬浮条不好看”，而是它默认占了用户的空间

一开始我也想过一个听上去很聪明的方案：能不能检测别的应用打开了菜单，然后让悬浮条自动避让？

后来很快把它否了。

跨应用悬浮层并不知道另一个软件的菜单在哪，也不能稳定区分一个弹出的控件是否值得避让。把这个能力做成产品承诺，最后大概率是一套猜错比猜对更多的规则。

所以这一版没有去做“假装懂所有应用”的自动避让。

更可靠的思路是：当它挡住你时，你能立即把它移开；当你不需要完整信息时，它能主动收起；当你需要继续说话时，又能确认它还在接收。

这也是 v1.8.0 这套交互的起点。

## 第一版做出来后，我发现“能拖动”根本不等于“拖得动”

最初的方案里，展开条左边有一个小点阵，当作拖动把手；收起后还有一个“贴边”按钮。

看起来功能都在。

实际一用，问题全出来了：拖动热区小，要精确点中；窗口拖起来会闪、跟手慢；贴边按钮也不容易理解——既然用户已经在拖，为什么还得再点一次，才能进入另一个模式？

这里我犯了一个很典型的产品错误：把“功能存在”当成“用户能自然发现并用好”。

后来我把拖动改成了 macOS 原生窗口拖拽。鼠标移到把手上，点阵会有蓝色背景和“拖动”提示；把手热区也扩大了。收起按钮用同一套反馈：平时只显示减号，鼠标移入才出现蓝色背景和“收起”。

文字不需要一直占着空间，但在用户需要理解动作时，必须出现。

贴边也不再是单独按钮。只有用户明确向屏幕外侧拖动一段距离后松手，窗口才会变成贴边球；普通拖动只是移动位置。这样能避免停在屏幕边缘时被误判为“要收起”。

## 收起以后，为什么还要留一小段字

收起态最开始有两个极端方案。

一个是只剩圆球和波形，足够干净；另一个是继续显示完整转写，信息最全。

它们都不合适。

只剩波形，用户只能知道麦克风似乎还开着，不知道自己的话有没有被接住。完整转写又重新占据屏幕，屏幕共享时还会泄露正在说的内容。

最后我选的是一条“微字幕胶囊”：保留动态波形、时长和最近一小段文字。它不跑完整跑马灯，只更新最新短语；如果处在屏幕共享等场景，也可以关闭收起态的实时文字，只留下录音状态。

这不是为了让动画更炫，而是为了在“看得见它在工作”和“它别碍着我”之间找一个能长期使用的平衡。

## 位置记忆，后来变成了这一版最容易被忽略的关键点

拖动做顺了，我以为位置记忆就是顺手的小功能。

结果第一版只记住了“靠左还是靠右”。你上次把悬浮条拖到某个位置，下次它可能跑到右侧中间。它记住的是一个停靠规则，却没有记住用户真正放下的位置。

更麻烦的是，录音时是长条，停止后会切到“正在处理”，收起又是胶囊。它们尺寸不同，如果每个状态都重新算位置，就会看起来像三个窗口在屏幕上跳来跳去。

现在的规则很简单：

- 第一次使用，默认底部居中；
- 主动拖放后，记录窗口中心相对屏幕的位置；
- 展开、收起和处理提示都围绕同一个中心改变尺寸；
- 窗口隐藏前再保存一次，下次快捷键唤起时恢复最后的位置和形态。

这听起来像小细节，但对高频工具来说，它其实是在回答一个很朴素的问题：你把东西放在哪里，它下次还认不认识那个位置？

## v1.8.0 先只发 macOS

这次已经发布 macOS v1.8.0，提供 DMG、ZIP 和 SHA256 校验文件。

Windows 暂时保持在 1.7.0。原因很简单：我现在没有 Windows 设备做真实验证，所以不打算为了版本号好看，把一个没测过的平台一起写进发布成功里。

等 Windows 设备恢复后，再补那边的测试和发布。

我现在对这版的结论是：它不是把语音输入“做得更显眼”，而是让它在需要出现时足够清楚，在不该打扰时能收得住。

真正高频的工具，最后比的往往不是功能有多少，而是它会不会在你最顺手的时候，突然变成那个碍事的东西。
